# Security Policy

## Supported Versions

Only the latest stable release receives security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take security bugs seriously. We appreciate your efforts to disclose them
responsibly, and we will make every effort to acknowledge your report.

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, send an email to `security@vibestream.org`. You should receive a
response within 48 hours. If for some reason you do not, please follow up via
email to ensure we received your original message.

Please include the following information in your report:

- Type of issue (e.g., buffer overflow, command injection, etc.)
- Full paths of source file(s) related to the manifestation of the issue
- The location of the affected source code (tag/branch/commit or direct URL)
- Any special configuration required to reproduce the issue
- Step‑by‑step instructions to reproduce the issue
- Proof‑of‑concept or exploit code (if possible)
- Impact of the issue, including how an attacker might exploit it

## Preferred Language

We prefer all communications to be in English.

## Disclosure Process

We will acknowledge your report, work on a fix, and then release an update.
We will also credit you for the discovery if you wish.

## Comments on this Policy

If you have suggestions on how this process could be improved, please submit a
pull request or open an issue (non‑security).
